# 子代理限制规则

对应文章：EP-008（子代理防卡死）、EP-009（多团队边界）

## 核心原则

子代理不是全权委托。它是有边界的执行单元。

## 禁止项

以下操作不允许子代理执行：

1. **禁止全链路操作**：不能同时负责前端 + 后端 + 数据库。一个子代理只做一件事。
2. **禁止长期服务**：不能启动一个不关闭的后台服务。如果需要验证服务，用健康检查后立即停止。
3. **禁止浏览器最终验收**：不能用浏览器自动截图、自动填表、自动点击来完成验收。验收由主代理人工确认。
4. **禁止修改全局配置**：不能改 ~/.hermes/config.yaml、team-registry.yaml 等系统级文件。
5. **禁止递归分派**：子代理不能再派子代理（除非使用 orchestrator 模式且配置了最大深度）。

## 必须项

以下规则必须遵守：

1. **必须设置 max_iterations**：每个子代理必须有最大步数限制（建议 15-30 步）。
2. **同一错误最多重试 2 次**：连续两次失败后停止，汇报给主代理，不要无限试。
3. **必须有明确的退出条件**：完成任务或达到限制后立即退出，不要等主代理 kill。
4. **必须指定 toolsets**：只开需要的工具集，不要全开。
5. **主代理负责最终验收**：子代理说"完成"不代表完成，主代理必须检查输出。

## 模板示例

```yaml
# 子代理分派示例
task:
  goal: "读取项目文件，修复前端样式 Bug"
  toolsets: ["terminal", "file"]
  context: |
    项目路径: ~/projects/xxx
    Bug 描述: xxx
    修改前必须备份原文件
  max_iterations: 20
```

## 常见翻车

- 子代理说完成了但没改 → 没有 max_iterations，它跑了 100 步还在试
- 子代理启动了服务没关 → 没有"禁止长期服务"规则，端口被占用
- 子代理把播报发到错误群 → 没有指定 toolsets，它读了不该读的团队文件
- 子代理卡死在一个循环里 → 同一错误重试超过 2 次没有停
